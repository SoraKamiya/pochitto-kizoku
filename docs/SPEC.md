# ポチッと貴族 - タッチパネル注文システム 実装指示書

## プロジェクト概要
焼き鳥居酒屋を想定した、QRコード注文+厨房リアルタイム反映のポートフォリオ用Webアプリケーション。個人開発の練習用。

## 技術スタック
- フロントエンド: React + Vite
- ルーティング: react-router-dom
- バックエンド: Firebase(Firestore + Firebase Hosting)
- デプロイ先: Firebase Hosting
- 状態管理: React標準のuseState / useEffect(追加の状態管理ライブラリは不要)

---

## 画面構成(同一Reactアプリ内、ルートで分岐)

| ルート | 画面 | 対象デバイス |
|---|---|---|
| `/order?table={トークン}` | 客席用注文画面 | スマホサイズ基準 |
| `/history` | 客席用注文履歴画面 | スマホサイズ基準 |
| `/kitchen` | 厨房用ディスプレイ画面 | タブレットサイズ基準 |

---

## 1. 客席用注文画面(`/order`)

### 卓の識別
- URLクエリパラメータ `table` にランダムトークンを持たせる(例: `/order?table=xR7k2m`)
- トークンと卓番号の対応はハードコードで管理。例:

```js
const TABLES = {
  "xR7k2m": 1,
  "p9Lm3q": 2,
  "a3f9x2": 3,
  "k8x2mQ": 4,
  "z7Yn5w": 5,
};
```

- URLの`table`パラメータが`TABLES`に存在しない場合は、エラー画面を表示する(「この卓は見つかりません」等のメッセージ)。
- 有効なトークンの場合、画面上部に常時「○番卓」を表示する。

### メニュー表示
- メニューデータはハードコードのJSON(コード内に直接記述、将来的な管理画面は不要)。
- カテゴリは以下の4つ。タブ切り替えで表示を切り替える。
  1. 焼き鳥
  2. サイドメニュー
  3. ドリンク
  4. デザート
- 各メニュー項目の構造例:

```js
{
  id: "item001",
  name: "もも串",
  price: 190,
  category: "焼き鳥",
  imageUrl: "/images/momo.jpg", // publicフォルダ内の画像を参照
  soldOut: false,
  hasSeasoningOption: true, // 塩・たれ選択可能かどうか
}
```

- `soldOut: true`の商品は「品切れ」表示にし、カートに追加できないようにする(手動でJSON内のフラグを編集して管理)。
- `hasSeasoningOption: true`の商品(焼き鳥類など)は、カート追加時に「塩」「たれ」を選択するオプションボタンを表示する。
- 焼き加減(よく焼き・レア等)の指定機能は実装しない(スコープ外)。

### カート機能
- カートアイコンをタップした時だけモーダルで表示する(常時表示はしない)。
- カート内の各商品は `+` / `-` ボタンで数量を変更できる。
- カートの内容は `localStorage` に保存し、ページのリロードやブラウザを閉じても内容が保持されるようにする。
- 「注文する」ボタンを押すと、はい/いいえの確認バーを表示し、「はい」を選択したら注文を確定する。

### 注文確定時の処理
- 注文確定時、1回の注文につき1つのFirestoreドキュメント(`orders`コレクション)を新規作成する。カート内の全商品をその1ドキュメントにまとめる。
- 注文データの構造例:

```js
// orders/{orderId}
{
  tableToken: "xR7k2m",
  tableNumber: 1,
  items: [
    { itemId: "item001", name: "もも串", price: 190, quantity: 2, seasoning: "たれ" },
    { itemId: "item010", name: "ビール", price: 480, quantity: 1 },
  ],
  totalPrice: 860,
  status: "pending", // "pending" | "cooking" | "done"
  createdAt: <Firestore Timestamp>
}
```

- 注文確定後、カートの中身は**クリアしない**。localStorageに「注文履歴」として蓄積していく(下記「注文履歴画面」参照)。
- 注文送信後は、トースト通知等で「ご注文を承りました」と表示する。

---

## 2. 客席用注文履歴画面(`/history`)

- localStorageに蓄積された、これまでの注文内容(品名・数量・金額)を一覧表示する。
- 各注文の調理状態(調理中・完了など)は表示しない。
- 画面下部に、これまでの全注文の合計金額(会計用の目安)を表示する。
- 決済機能・会計処理は実装しない。金額表示のみ。

---

## 3. 厨房用ディスプレイ画面(`/kitchen`)

### 認証
- 簡易パスワード認証。パスワードはフロントエンドのコード内にハードコードする(環境変数不要、Firebase Auth不要)。
- 一度認証したら、その端末では再入力を求めなくてよい(共有タブレット前提)。

### 注文の表示
- Firestoreの`orders`コレクションをリアルタイム監視(`onSnapshot`)し、新しい注文が入ったら即座に画面に反映する。
- 表示順序: 注文が来た順(`createdAt`の昇順、古い順)。
- 卓ごとにグルーピングはせず、1注文=1チケットとして時系列に並べる。
- 各チケットには卓番号・品名・数量・味付け(該当する場合)を表示する。

### ステータス管理
- 各注文は以下の3段階のステータスを持つ。
  1. `pending`(未着手)
  2. `cooking`(調理中)
  3. `done`(完了)
- 「調理開始」ボタンで `pending → cooking`、「完成」ボタンで `cooking → done` に更新する(Firestoreの該当ドキュメントを更新)。
- `done`になった注文は、メイン画面から「完了済み」リストへ移動し、そこで確認できるようにする(完全に削除・非表示にはしない)。

## Firestore構成

### コレクション設計
- `orders`コレクションのみ使用(卓情報・メニュー情報はハードコードのため、Firestoreに別コレクションは不要)。

### セキュリティルール
- 読み書きともに認証なしで許可する(全開放)。ポートフォリオ用途のため厳密なアクセス制御は行わない。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /orders/{orderId} {
      allow read, write: if true;
    }
  }
}
```

---

## 画像管理
- メニュー画像は `public/images/` フォルダに直接配置し、コード内では相対パス(例: `/images/momo.jpg`)で参照する。
- 外部URLやFirebase Storageは使用しない。

---

## スコープ外(今回は実装しない機能)
- 会計・決済機能全般(合計金額の表示のみ行い、決済処理・レジ連携は行わない)
- 焼き加減などの調理指定オプション
- メニューの管理画面(CRUD機能)
- 卓トークンの動的生成・管理画面
- 客側での調理状況(未着手/調理中/完了)のリアルタイム確認
- Firebase Authによる本格的なログイン機能
- IPアドレス制限などの端末制限

---

## 実装の優先順位(推奨)
1. Firebaseプロジェクトのセットアップ(Firestore + Hosting)
2. メニューデータ(JSON)と画像の準備
3. 客席用注文画面(`/order`): メニュー表示 → カート → 注文送信
4. 厨房用ディスプレイ画面(`/kitchen`): リアルタイム受信 → ステータス管理
5. 客席用注文履歴画面(`/history`)
6. エラーハンドリング(不正な卓トークン)
7. Firebase Hostingへのデプロイ
